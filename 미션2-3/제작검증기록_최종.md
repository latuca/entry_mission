## 10. 수정할 문제 찾기

| 추가로 본 조건 | 방법 | 관찰 |
|---|---|---|
| 섹션 3~6의 작은 글씨 읽기 | 글자를 잠시 투명하게 하고 뒤 배경만 캡처한 뒤, 글자색을 배경 위에 합성해 명도 대비(WCAG 방식)를 계산 | 섹션 5 안내 문장 대비 중앙값 3.4:1(1440px)·3.2:1(390px), 밝은 창 불빛 위에서는 2.0:1 이하. 섹션 5 설명 문장·머리말도 중앙값 4.1~4.8:1 |
| 휴대폰에서 점 내비게이션 | 390×844 터치 화면에서 점 크기와 이름표 표시 여부 측정 | 점 14×14px, 이름표가 항상 보이지 않음(투명도 0) |
| 가로로 눕힌 휴대폰·태블릿 | 844×390, 740×360, 667×375, 768×1024, 1024×768 첫 화면 캡처와 요소 위치 측정 | 844×390·740×360에서 SCROLL 표시가 소개 문장과 1~5px 겹침, 기체 날개가 "We Fly the Dream:" 줄에 걸침. 태블릿 2종은 이상 없음 |
| 화면 200% 확대(1440×900 → 720×450) | 같은 측정 | 겹침·좌우 스크롤 없음 |

판단 기준(작은 글씨 4.5:1, 누르는 대상 24×24px 이상)은 WCAG 2.2 AA를 참고했다. 기획서의 완료 기준에는 없는 항목이므로 **기준 밖의 개선**으로 분류한다.

### 수정 1. 섹션 5의 작은 글씨가 배경에 묻힘 (v1 → v2)

| 항목 | 내용 |
|---|---|
| 테스트 내용 | 1440×900과 390×844에서 섹션 5로 이동해 화면을 캡처하고, 안내 문장(`실제 도입 방식은…`)·설명 문장·머리말의 명도 대비를 측정한다. |
| 예상 결과 | 모든 섹션의 작은 글씨가 배경과 뚜렷이 구분되어 읽힌다(대비 4.5:1 이상). |
| 실제 결과 (v1) | 섹션 5는 아래쪽이 밝은 하늘색으로 바뀌고 도시 창 불빛이 밝아지는데, 그 위에 연한 글씨가 놓였다. 안내 문장 대비 중앙값 3.4:1(1440)·3.2:1(390), 창 불빛 위 일부는 2.0:1 이하였다. 화면에서 "제도와 서비스 설계에" 부분이 창 불빛과 겹쳐 끊겨 보였다. 섹션 3·4는 같은 문장이 5.0~5.7:1이었다. |
| AI에게 전달한 요청 | "섹션 5로 내려가면 배경 아래쪽이 밝아지는데, 맨 아래 안내 문장(실제 도입 방식은…)이 밝은 창 불빛과 겹쳐 글자가 끊겨 보여. 측정해 보니 대비가 3.4:1 정도야. 섹션 5의 분위기(밝아지는 하늘)는 유지하면서 작은 글씨가 잘 읽히게 고쳐 줘. 다른 섹션과 카드 크기는 바꾸지 말아 줘." |
| 수정 내용 | 섹션 5 배경의 아래쪽 밝기와 도시 밝기를 낮춤. 안내 문장(섹션 3·4·5 공통)에 어두운 반투명 받침을 넣고 글자색을 진하게 함. 섹션 5 설명 문장·머리말 색을 한 단계 밝게 함. 인쇄용 스타일에서는 받침을 뺌. |

| 수정 이유 | 고치지 않으면 섹션 5를 보는 사람, 특히 휴대폰을 밝은 곳에서 보거나 시력이 약한 사람이 "실제 도입 방식은 달라질 수 있다"는 안내를 읽지 못한다. 이 문장은 기획서가 정한 "가능성으로 서술" 원칙을 보완하는 문장이어서, 읽히지 않으면 확정된 계획처럼 오해할 수 있다. |

| 관찰한 현상 (v4) | 휴대폰에서 스크롤하는 동안 배경 속 기체가 멈춰 있다가 섹션이 바뀌는 순간 한 번에 움직였다. 390×844 터치 화면에서 섹션 2→5를 80px씩 42단계 스크롤했을 때 기체가 거의 안 움직인 단계(1px 미만)가 18개, 한 단계 최대 이동이 79px였다. (측정은 스크롤 스냅을 끄고 v4·v5에 같은 조건으로 수행) |
| AI에게 전달한 요청 | "이 피드백을 바탕으로 v5최종 수정해서 나한테 줘봐" (피드백 칸의 내용과 반영 내용 칸의 "v5에서 백그라운드 움직임을 핸드폰에서 더 자연스럽게 연출"을 함께 전달) |
| 수정 내용 | 스크롤 위치에 따라 기체의 위치·크기·투명도를 섹션 사이에서 이어서 계산해 움직임. 별은 기체와 다른 속도로 움직임. 빠르게 스크롤하면 기체가 살짝 기울었다가 돌아옴. "동작 줄이기" 설정에서는 실행하지 않음. 도시 야경도 움직여 봤으나 저사양 휴대폰을 흉내 낸 측정(CPU 4배 감속)에서 프레임이 빠져 제외함. |
| 수정 후 테스트 결과 (v5) | 같은 측정에서 멈춘 단계 18 → 1, 한 단계 최대 이동 79px → 26px. 회귀 테스트: 기준 1~8 모두 통과, 인쇄 5쪽, 점 내비게이션(28px, 1.8초 이름표)·가로 화면 겹침(SCROLL 간격 56px)·섹션 5 대비(중앙값 10.9:1)는 v4와 같음. 동작 줄이기에서는 기체·도시에 움직임 스타일이 붙지 않음. 저사양 흉내 측정(CPU 4배 감속, 6초 스크롤)의 프레임 간격 중앙값은 v4·v5 모두 16.7ms이며, 하위 5%는 v4 16.8ms, v5 33.3ms로 v5가 일부 프레임에서 더 늦었다. 50ms를 넘긴 프레임은 v4·v5 모두 0~1개였다. |
| 수정 이유 | 고치지 않으면 휴대폰 사용자는 스크롤하는 동안 배경이 멈춰 있다가 갑자기 튀는 것처럼 보여, 사용자가 말한 "영상미"가 느껴지지 않고 페이지가 끊겨 보인다. |
| 한계 | 이 측정은 그래픽 가속이 없는 작업 환경에서 수행했다. 실제 휴대폰에서 얼마나 부드러운지는 작성자가 직접 확인해야 한다. |
| 작성자 확인 | 내 휴대폰에서 `UAM소개_v5.html`을 스크롤해 기체가 이어서 움직이는 것을 확인했다 |

## 13. 이번 미션의 AI 활용 범위

- Claude(Opus 5.5)가 한 일: v1 추가 테스트로 문제 찾기, 측정 스크립트 작성·실행, 관찰을 바탕으로 한 수정 요청문 초안 작성, 수정 3건(v2~v4) 반영, 사용자 피드백을 반영한 v5 제작, 버전별 회귀 테스트, 이 기록의 10~12장 정리.
- Claude(Sonnet 5.5)가 한 일: 기획서를 v4·v5에 맞게 수정, 이 기록의 v5 내용 반영.
- 작성자가 직접 한 일: 미션 요청 전달, 수정 요청문 검토, 각 수정 결과를 자신의 브라우저에서 재확인("작성자 확인" 칸), 사용자 테스트 진행과 12장의 참여자·행동·피드백·반영 방향 작성, 기획서 최종 검토.
- 참고: 11장의 "AI에게 전달한 요청"은 Claude가 측정한 현상을 원인 추측 없이 정리한 요청문이며, 같은 대화 안에서 Claude가 그 요청대로 수정했다.
