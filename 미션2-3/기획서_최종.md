# 기획서: UAM 소개 페이지 "We Fly the Dream"

> 작성: AI와의 질의응답으로 초안 작성 후, 작성자가 검토·수정 (아래 "11. 사용한 AI 서비스와 모델" 참고)

> 표시 방법: 최초 기획에서 바뀐 부분은 해당 줄 끝에 **(v4 반영)**으로 표시했다. 바뀐 내용 전체는 13장에 모았다.

## 1. 대상 사용자

- **주된 사용자:** 작성자 본인 (창업 아이템인 UAM을 소개하는 용도)
- **방문자:** 불특정 다수. UAM을 처음 접하거나 이름만 들어본 사람
- **사용 상황:** 링크를 열어 스크롤하며 UAM이 무엇이고 어떤 가치가 있는지 한 번에 이해한다. 전문 지식은 필요하지 않다.
- **사용 기기:** 데스크톱, 세로·가로 휴대폰, 태블릿. 마우스가 없는 터치 화면에서도 같은 흐름으로 쓸 수 있어야 한다. **(v4 반영)**

## 2. 사용 목적

한국에서는 아직 상업화 전이고 안전 규제도 있어서 접하기 어려운 UAM(도심항공교통)을 쉽게 소개한다. 방문자가 다음 세 가지를 이해하는 것이 목적이다.

1. UAM으로 어떤 수익 모델을 만들 수 있는가
2. UAM이 실생활에 어떤 도움을 주는가
3. UAM이 사회적 약자에게 어떤 도움을 줄 수 있는가

방문자가 열자마자 가장 먼저 확인할 내용은 첫 문장이다.

> **We Fly the Dream: 우리는 도시의 지도를 바꿉니다.**

## 3. 화면 구성과 동작

### 3-1. 디자인 방향

- **분위기:** 미래지향적이고 시각적 자극이 있는 풀스크린 구성. 큰 문장 중심, 한 화면에 한 메시지.
- **색상:** 짙은 남색~검정 배경(`#050B18`)에 차갑고 시원한 포인트 색. 청록(`#22D3EE`), 하늘색(`#7DD3FC`), 얼음빛 흰색(`#E6F4FF`). 따뜻한 색은 쓰지 않는다. 섹션 3·4·5는 배경이 청록 → 하늘색 → 밝은 푸른빛으로 바뀐다. **(v4 반영: "초안" 표시 삭제)**
- **작은 글씨 가독성:** 밝은 배경 위의 작은 글씨는 배경과 뚜렷이 구분되어야 한다. 섹션 5처럼 배경이 밝아지는 구간은 아래쪽 밝기를 낮추고, 안내 문장에는 어두운 반투명 받침을 둔다. **(v4 반영: 수정 1)**
- **글꼴:** 한글은 Pretendard, 영문 헤드라인은 Space Grotesk. 불러오지 못하면 기본 글꼴로 대신한다.
- **레퍼런스에서 가져온 요소:** 글자 등장 효과, 배경 전환, 큰 문장 중심 구성. (레퍼런스의 색상, 사진, 문구는 가져오지 않았다.)

### 3-2. 섹션 구성 (동등한 비중)

| 순서 | 섹션 | 큰 문장 | 배경 |
|---|---|---|---|
| 1 | 첫 화면 | We Fly the Dream: 우리는 도시의 지도를 바꿉니다. | 짙은 남색 + 야간 도시 위를 나는 UAM 기체(코드로 그림) |
| 2 | UAM이란? 지금 어디까지 왔나 | 하늘이 새로운 도로가 됩니다. | 짙은 남색~남청색, 도시 야경, 작아진 기체 |
| 3 | 수익 모델 | 하늘에서 새로운 사업이 시작됩니다. | 청록 계열 |
| 4 | 실생활 도움 | 이동 시간이 줄면, 하루가 달라집니다. | 하늘색 계열 |
| 5 | 사회적 약자 지원 | 닿기 어려웠던 곳까지, 하늘이 이어줍니다. | 밝은 푸른빛 (아래쪽은 글씨가 묻히지 않을 만큼만 밝게) |
| 6 | 마무리와 출처 | 도시의 지도는 다시 그려집니다. | 다시 어두운 배경 |

세 주제(섹션 3~5)는 **카드 4개씩, 같은 높이와 분량**으로 배치한다. 화면 너비 1440·390·360px에서 세 섹션의 카드 높이와 섹션 높이가 같다. **(v4 반영: 카드 수 확정)**

### 3-3. 섹션별 내용 (소개 수준, 깊이 들어가지 않는다)

- **섹션 2:** UAM이 무엇인지 한 문장으로 설명하고(전기 동력, 수직 이착륙, 다른 교통과 연계 세 가지를 짧은 표지로 요약), "한국은 지금" 상자에서 아직 상업 운항 전이며 안전 기준과 기술을 실증하며 갖춰 가는 단계라는 점만 짧게 언급한다. 규제 조항, 인증 절차, 법령 이름 같은 세부 내용은 적지 않는다. **(v4 반영)**
- **섹션 3 (수익 모델):** 카드 4개. 도심 이동 서비스, 관광·레저 노선, 응급·물류 운송, 연계 사업(기체 운영·정비, 이착륙장 운영, 예약 플랫폼). 구체적인 금액이나 시장 규모 수치는 넣지 않는다. 하단에 "소개를 위한 예시이며, 투자 권유가 아닙니다." 문구를 둔다. **(v4 반영)**
- **섹션 4 (실생활 도움):** 카드 4개. 이동 시간 단축, 교통 혼잡 우회, 먼 곳과의 연결, 다른 교통과의 환승. 짧은 문장으로 소개하고 "~할 수 있습니다"로 쓴다. 하단에 "상용화 이후 기대할 수 있는 모습을 소개한 것입니다." 문구를 둔다. **(v4 반영)**
- **섹션 5 (사회적 약자 지원):** 카드 4개. 교통이 불편한 지역 주민, 이동이 어려운 고령자, 휠체어 이용 장애인, 응급 환자 이송. 모두 "가능성이 있습니다"로 서술하고 단정하지 않는다. 하단에 "실제 도입 방식은 앞으로의 제도와 서비스 설계에 따라 달라질 수 있습니다." 문구를 둔다. **(v4 반영)**
- **섹션 6:** 마무리 문장, "We Fly the Dream." 태그, 참고한 자료 4건(4-3 참고), 기준 시점과 안내 문구.

### 3-4. 동작

- 페이지를 열면 첫 문장이 글자 단위로 차례로 나타난다(약 2초). "We Fly the Dream:"과 한글 문장이 두 줄로 보인다.
- 스크롤하여 다음 섹션에 들어가면 큰 문장이 아래에서 떠오르며 나타나고, 배경이 부드럽게 전환된다. 이미 본 섹션으로 돌아와도 다시 떠오른다. **(v4 반영)**
- 화면 한쪽에 현재 섹션을 보여주는 점 내비게이션이 있고, 점을 누르면 해당 섹션으로 이동한다.
  - 마우스가 있는 화면: 점에 마우스를 올리면 섹션 이름이 보인다.
  - **터치 화면: 누르는 영역을 28×28px로 키우고, 섹션이 바뀌거나 점을 누르면 현재 섹션 이름이 1.8초 동안 보였다 사라진다. (v4 반영: 수정 2)**
- 모바일과 데스크톱 모두 같은 흐름으로 보인다. **높이가 낮은 가로 화면(높이 520px 이하)에서는 SCROLL 표시와 기체 위치를 조정해 소개 문장·제목과 겹치지 않게 한다. (v4 반영: 수정 3)**
- 운영체제의 "동작 줄이기" 설정을 켠 방문자에게는 글자 등장·배경 전환·기체 흔들림 등 모든 애니메이션을 생략하고 내용을 바로 보여준다.
- 인쇄하면 어두운 배경과 장식을 빼고 흰 바탕에 6개 섹션 전체와 출처를 출력한다(A4 5쪽). **(v4 반영: 필수는 아님, 구현된 보조 동작)**

## 4. 필요한 자료

### 4-1. 배경 이미지

- **적용한 방식(A): 코드로 직접 그린 이미지.** CSS와 SVG로 UAM 기체(전기 수직이착륙기, 일반 형태), 3겹 도시 야경, 별, 옥상 이착륙장을 그렸다. 출처와 사용 권한 문제가 없고, 다른 파일 없이 열린다. 특정 제조사의 기체 형상이나 로고를 쓰지 않았고 이미지 안에 글자가 없다. **(v4 반영)**
- **사실감 지침 (HTML 제작 단계에서 Opus 5.5에게 전달했고 적용됨):**
  - 최대한 사실적이되 미래지향적인 느낌으로 그린다.
  - 여러 겹의 그라데이션, 외곽 조명(림 라이트), 빛 번짐(glow), 흐림 효과(blur), 원근감, 안개·구름 레이어를 사용한다.
  - 특정 제조사의 기체 형상이나 로고를 그대로 재현하지 않고, 일반적인 전기 수직이착륙기(eVTOL) 형태로 직접 디자인한다.
  - 이미지 안에는 글자를 넣지 않는다.
- **한계:** 코드로 그린 그림은 실제 사진만큼의 사실감을 내기 어렵다.
- **선택 사항(이번 최종본에서는 사용하지 않음): 이미지 생성 도구용 프롬프트 (참고용).** 사진 수준의 사실감이 필요하면 별도 이미지 생성 도구로 만든 뒤 `https://`로 시작하는 인터넷 주소로 삽입한다. 이 경우 사용한 도구 이름과 이용 조건을 아래 표에 기록한다. 이번 최종본은 사진을 쓰지 않았으므로 기록할 항목이 없다. **(v4 반영)**
  - 첫 화면용: `Photorealistic eVTOL air taxi hovering above a futuristic city skyline at blue hour, dark navy and cyan color palette, volumetric light, rim lighting, cinematic wide shot, shallow depth of field, ultra detailed, no text, no logos`
  - 섹션 5용: `Small eVTOL aircraft landing on a rooftop vertiport above a quiet mountain village at dawn, cool blue tones, soft fog, cinematic, ultra detailed, no text, no logos`

## 5. 완료 기준

특정 행동에 따른 기대 결과로 확인한다. 1~9는 최초 기획의 기준이고, 10~12는 수정 과정에서 추가한 기준이다. **(v4 반영)**

1. 페이지를 열면 어두운 배경에서 "We Fly the Dream: 우리는 도시의 지도를 바꿉니다."가 글자 단위로 나타난다. (0.4초 시점에는 일부 글자만, 3.6초 시점에는 전부 보이고 두 줄로 표시)
2. 첫 화면 뒤에 UAM 기체 이미지가 배경으로 보인다.
3. 아래로 스크롤하면 섹션 2~6이 순서대로 나타나고, 섹션이 바뀔 때마다 큰 문장이 떠오르며 배경이 전환된다. 이미 본 섹션으로 돌아와도 다시 떠오른다.
4. 섹션 3, 4, 5(수익 모델, 실생활 도움, 사회적 약자 지원)가 같은 크기와 분량(카드 4개, 카드 높이 동일)으로 보인다.
5. 점 내비게이션의 세 번째 점을 누르면(데스크톱 클릭, 휴대폰 터치) 수익 모델 섹션으로 이동한다.
6. 다른 파일이나 로그인 없이 열린다.
7. 휴대폰 화면 크기(360px, 390px)에서 글자가 잘리거나 좌우 스크롤이 생기지 않는다.
8. "동작 줄이기" 설정을 켜면 애니메이션 없이 내용이 바로 보인다.
9. 규제 조항이나 인증 절차 같은 세부 내용은 페이지에 나오지 않는다.
10. **(추가)** 섹션 2~6의 작은 글씨(머리말, 설명 문장, 안내 문장)가 배경과 뚜렷이 구분된다. 배경을 캡처해 측정한 명도 대비가 **중앙값 기준 4.5:1 이상**이다. (WCAG 2.2 AA 참고)
11. **(추가)** 터치 화면에서 점 내비게이션의 누르는 영역이 **24×24px 이상**이고, 현재 섹션 이름을 알 수 있다.
12. **(추가)** 가로로 눕힌 휴대폰(예: 844×390, 740×360, 667×375)의 첫 화면에서 제목, 소개 문장, SCROLL 표시, 기체 그림이 서로 겹치지 않는다.

## 6. 필수 기능과 추가 기능

**필수 기능 (v4에 구현됨)**
- 풀스크린 섹션 6개
- 글자 등장 효과
- 섹션별 배경 전환
- 점 내비게이션 (터치 화면 대응 포함) **(v4 반영)**
- 하단 출처 표시
- 모바일 대응 (세로·가로) **(v4 반영)**
- 동작 줄이기 대응

**구현했으나 필수는 아닌 기능 (v4 반영)**
- 인쇄용 스타일 (흰 바탕, A4 5쪽)

**추가 기능 (이번 구현에서는 제외, 후속 단계에서 검토)**
- 영문/국문 전환
- "관심 등록" 또는 문의 기능 (서버가 필요하므로 이번에는 제외)
- 사진 수준 이미지를 `https://` 주소로 삽입 (4-1 선택 사항). 이번 최종본은 코드로 그린 이미지만 사용했다.

## 7. 한계 및 비목표 (3가지)

1. 로그인, 서버, 챗봇·AI 기능, 입력 폼 제출은 구현하지 않는다. (v4에는 `form`, `input`, `textarea`가 없고 외부로 보내는 요청은 글꼴 2건뿐이다.) **(v4 반영: 확인 결과)**
2. 안전 규제의 세부 내용(조항, 인증 절차 등)은 다루지 않고 "안전 기준을 갖추는 단계"로만 소개한다. 규제와 상업화 현황은 실시간으로 갱신하지 않으며 작성 시점(2026년 11월) 기준이며, 페이지 하단에 그렇게 밝힌다.
3. 실제 운항 예약이나 투자 상담은 제공하지 않는다. 수익 모델은 소개 수준이며 투자 권유가 아니다. 섹션 3과 하단 문구에 같은 내용을 적는다.

## 8. 제약 사항

- 최종 제출물은 `UAM소개_v4.html`(또는 피드백 반영 후 최종본), 이 `기획서.md`, `제작검증기록.md` 3개이다. HTML은 CSS와 JavaScript를 같은 파일에 포함한 1개 파일이다. **(v4 반영: 이전 "이 기획서 1개" 문구 수정)**
- 사진은 로컬 파일이 아니라 `https://`로 시작하는 인터넷 주소로 삽입한다. (이번 최종본은 사진을 쓰지 않는다.)
- 로그인, API 키, 서버가 필요한 기능은 포함하지 않는다.
- 외부 자료(글꼴)는 사용 권한을 확인한 뒤 인터넷 주소로 불러오고, 별도 첨부하지 않는다. 다른 컴퓨터에서 불러오지 못해도 페이지가 정상적으로 열리고 읽혀야 한다. **(v4 반영)**
